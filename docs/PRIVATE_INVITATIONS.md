# Invitations aux ligues privées (BET-321)

Un membre peut copier le lien ou partager un PNG local et ce lien. L'aperçu volontaire contient le nom, l'effectif et les points du podium **anonyme**, jamais les pseudos ni les identifiants des autres membres. Ces champs sont limités et échappés. Le nom et les points du lien sont un instantané fourni par l'expéditeur, explicitement non vérifié ; ils ne confèrent aucun droit et le classement réel reste soumis à la RLS après adhésion. Les anciens liens avec code seul fonctionnent toujours.

L'image jointe est l'aperçu du partage natif. Un lien copié seul conserve les métadonnées génériques du site ; aucun serveur public de rendu de ligue ni nouvel accès anonyme aux tables n'est créé. Sans partage natif de fichiers, le PNG est téléchargé et le lien peut être copié séparément.

Le téléphone invité affiche immédiatement un formulaire email et l'accord 18+/règlement. `signInWithOtp` du fournisseur Supabase existant peut créer un compte confirmé par email, sans mot de passe ni newsletter. Le retour est limité à l'origine et au chemin de l'application, avec le code normalisé. Le pseudo initial est attribué par le mécanisme serveur existant et reste modifiable dans le profil. Le parcours classique de connexion et de réinitialisation de mot de passe reste disponible.

Le souhait explicite « recevoir mon lien et rejoindre » est conservé en session pendant 24 h maximum. Même navigateur : reprise et adhésion via la RPC existante, une fois les données serveur chargées. Autre navigateur ou session perdue : le code du lien restaure la destination, puis un bouton demande l'adhésion. Aucun paramètre URL ne suffit à autoriser une adhésion automatique. Annulation, adhésion et déconnexion effacent l'intention ; les erreurs de connexion et ligues pleines désactivent la reprise automatique. Aucun email n'est conservé dans ce brouillon. Les limites et erreurs métier restent côté serveur : code invalide/régénéré, tentatives et 50 membres maximum.

Validation : 494 tests Node ; recette navigateur à 390/1440 px (email et transport simulés, aperçu échappé, reprise unique, consentement absent, ligue pleine, annulation) ; méthode réelle `magicInvite` testée avec transport Supabase simulé ; recette PostgreSQL PGlite prouvant le refus du 51e membre et l'admission après libération d'une place. Configuration de production vérifiée en lecture : inscription et email activés, confirmation obligatoire, URL canonique correcte. Aucun email réel ni message WhatsApp/iMessage n'a été envoyé. La réception du lien et le parcours depuis WhatsApp sur un téléphone réel restent à valider manuellement ; la simulation ne prouve pas la délivrabilité ni le comportement des navigateurs intégrés.
